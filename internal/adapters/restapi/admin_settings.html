Search & rankingBM25 weights, semantic pool, link authority, fuzzy matching

Ranking





Defaults: alpha 0.5, k1 1.2, b 0.75, title weight 2. Values outside 0–1 (alpha, b) or below 0 (k1) are clamped; title weight below 1 falls back to the default. A title weight change only takes effect for documents crawled or re-crawled afterward -- it isn't retroactively applied to already-indexed content.

Search



On Postgres with the pgvector extension installed, fills the semantic candidate pool from a real nearest-neighbor index instead of a bounded brute-force sample. Has no effect on SQLite/MySQL, or a Postgres server without the extension -- those always use the brute-force sample regardless of this setting. Uncheck to force the brute-force path for troubleshooting even when ANN is available.

Defaults: 10 results, 200 candidates, ANN enabled. Every BM25 match is always scored too; the pool size only bounds how many additional documents get sampled/searched for a purely semantic match.

Embeddings

Both may be enabled at once, so search can switch which one it reads (below) without ever needing a recompute -- the other is already kept warm on every crawl. At least one must stay enabled. Enabling this one means every crawl (and any recompute) also pays for an HTTP Embed call per document, against the rate limit below, even while it isn't the one active for search.








Default: hash. Switching providers takes effect only after every process (search, admin, crawl) is restarted -- unlike every other setting on this page, it isn't picked up live, since the embedding column's size is fixed at process startup. It also changes the vector space entirely: existing stored embeddings become meaningless to compare against newly computed ones until every document's embedding is recomputed -- no re-crawl needed, since the indexed text itself doesn't change. See Embeddings to list available models or trigger a recompute.

Link authority



Defaults: weight 0 (no effect on ranking until raised), 60 minute interval (minimum 5). A recompute also always runs right after a crawl finishes, since that's when the link graph actually changes.

Fuzzy matching

When a query term has no matches at all, look it up against the index's vocabulary for a near-miss (within the edit distance below) and use that instead for scoring -- the displayed query is never rewritten, only what's used behind the scenes.


Defaults: enabled, distance 2. A term that already matches something is never touched.

CrawlingFetch limits, rendering, link scope, version history

Crawler










Defaults: 8s timeout, 20 pages, 50 characters minimum, 250ms delay, 5120 KB (5 MB) response cap, 200 retained crawl jobs, no rendering, seed's domain including subdomains. Rendering a page in a real browser is much slower than a plain fetch (each page opens its own browser tab) and downloads that browser engine the first time it's ever used -- turn it on only for sites whose real content needs JavaScript to appear. "Seed's domain, including subdomains" follows e.g. blog.example.com and example.com from a seed of www.example.com, but not example.org. "Same domain, any subdomain, any top-level domain" is broader still — from a seed of example.com it also follows example.org and www.example.de (the same domain name, any subdomain, under any TLD), but not other.com.

Documents


Default: 5. A document that's never changed always has exactly one version regardless of this setting -- it only bounds how much prior history a frequently-changing page accumulates. Lowering it prunes existing extra versions the next time that document is re-crawled, not immediately.

Content rulesBlocked and boosted terms and domains

Blocked



Word matching uses the same tokenization as search, so casing and punctuation don't matter.

Boosted



A factor above 1 ranks a match higher, below 1 lower. Matching factors multiply together; zero or blank is ignored.

SystemDatabase connection pool, session length

Database connection pool




Defaults: 25 open, 25 idle, 5 minute lifetime. SQLite always keeps a single connection regardless of these values, since it serializes writers at the file level; a running process re-reads and re-applies these within about 10 seconds of a save, but the effect on already-open connections is limited to pool bookkeeping (idle/lifetime), not an instant reconnect.

Session


Default: 12 hours. Applies to sessions created after saving.
