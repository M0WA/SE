i"stdio" spawns Command as a child process and speaks MCP over its stdin/stdout -- for a locally installed server. "http" connects to Base URL over MCP's Streamable HTTP transport -- for a remote/third-party server.
iThe executable to spawn, e.g. /usr/bin/searchengine-mcp-web -- an absolute path or one resolvable on this process's own PATH.
iCommand-line arguments passed to Command, one per line. Leave empty for none. Built-in servers: mcp-sandbox accepts -network (enable network access, default off), -memory, -cpus, -pids-limit, -timeout (resource limits), -dns=<ip>,<ip> (DNS servers, only meaningful with -network), -host-dns (use this host's own real DNS servers instead of Docker's default, merged with -dns if both are set), -host-network (run with Docker's host networking instead of the default bridge network -- DNS just works with no -dns/-host-dns needed, but this is a bigger privilege elevation than plain -network: the sandbox can see/bind the host's own network interfaces directly). mcp-files accepts -base-url (default http://127.0.0.1:8080).
iOptional. Sent as an "Authorization: Bearer" header on every request to Base URL -- only meaningful for an "http" server that requires auth; ignored for "stdio". Encrypted at rest and never shown again after saving.
iLeaving API key blank above keeps whatever key is already stored -- check this box instead to actually delete it (e.g. the remote server no longer requires auth).
iThis is NOT where you describe what the server does -- each tool's own name/description (shown by "List tools" above) comes live from the server itself and already tells the model that. Prompt is for extra cross-tool steering beyond those descriptions, e.g. "after searching, fetch the top 3 results" -- injected as its own system message only while this server is active (see "Gated by web search" below), in addition to the endpoint's own persistent system prompt (Settings -> Chat), not instead of it. Leave empty if the tool descriptions already say everything the model needs.
iWhen checked, this server (and its Prompt) is only active when the chat's Web toggle is on -- the same Search the web setting (Settings -> Chat) or its per-question override, not a separate control. When unchecked, this server is active whenever Enabled is checked, regardless of the Web toggle.
