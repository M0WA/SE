se.

The chat-completions backend the public search page's Chat mode talks to, and whether it grounds its answers in a live web search -- this instance's own index can be blended into those results too, by adding it as a SearXNG engine (see packaging/searxng-engine/README.md) rather than as a separate mechanism here.

Chat endpoint

iTurns the chat mode toggle on the public search page on or off.
iOpenAI-compatible chat-completions API base URL, e.g. http://localhost:8000/v1 -- POSTed to <base_url>/chat/completions.
iSent as the chat request's model field.
iSent as an Authorization: Bearer header. Optional for a local server. Leave blank when editing to keep the currently stored key.

System prompt

iInjected as a system message before every turn, on every question -- never shown in the chat itself, and never dropped even when older messages are trimmed to fit the context budget.

Web search

iWhen on (as the default, or the chat page's own per-question Web toggle), every chat hook gated to web search becomes available to the model -- it decides whether to invoke a "web_search"/"web_fetch" hook, not this setting.
iA self-hosted SearXNG instance's base URL, e.g. http://127.0.0.1:8888 -- passed to every active hook's script as the WEB_SEARCH_BASE_URL environment variable, so a "web_search" hook script knows which instance to query.

Context budget

Roughly how the system prompt, active chat hooks' own prompts, and the max conversation length below break down -- estimated by character count, the same rough method the backend itself uses for trimming, not real model tokenization.

iBounds how much conversation (web-search context plus message history, estimated by character count) is sent to the model per turn. Older messages are dropped first, oldest to newest -- the most recent message is always kept. 0 disables trimming and sends the full conversation as-is, which can eventually exceed the model's own context limit.
