se.

The chat-completions backend the public search page's Chat mode talks to, and whether it grounds its answers in a search of the index.

Chat endpoint

iTurns the chat mode toggle on the public search page on or off.
iOpenAI-compatible chat-completions API base URL, e.g. http://localhost:8000/v1 -- POSTed to <base_url>/chat/completions.
iSent as the chat request's model field.
iSent as an Authorization: Bearer header. Optional for a local server. Leave blank when editing to keep the currently stored key.

System prompt

iInjected as a system message before every turn, on every question -- never shown in the chat itself, and never dropped even when older messages are trimmed to fit the context budget.

Retrieval-augmented answers

iWhen on, each message first runs a search and the top results are given to the chat model as context, with sources cited in the answer. When off, messages go straight to the model with no connection to the indexed corpus.
iHow many top search results are given to the chat model as context when RAG is enabled.
iBounds how much conversation (RAG context plus message history, estimated by character count) is sent to the model per turn. Older messages are dropped first, oldest to newest -- the most recent message is always kept. 0 disables trimming and sends the full conversation as-is, which can eventually exceed the model's own context limit.

Web search

iWhen on, each message first runs a live web search (via the SearXNG instance below) and the top results are given to the chat model as context, with sources cited in the answer. Independent of RAG above -- both can be on at once.
iA self-hosted SearXNG instance's base URL, e.g. http://127.0.0.1:8888 -- queried at <base_url>/search?q=...&format=json.
iHow many top web search results are given to the chat model as context when web search is enabled.

Context budget

Roughly how the system prompt, active chat hooks' own prompts, and the max conversation length above break down -- estimated by character count, the same rough method the backend itself uses for trimming, not real model tokenization.
